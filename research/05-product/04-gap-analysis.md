## 2. สิ่งที่เพิ่มให้แล้ว

**นำเข้าเอกสาร** — อ่านในเบราว์เซอร์ทั้งหมด ไม่อัปโหลดไปไหน ไม่ใช้ไลบรารีภายนอก

| ชนิด | สถานะ |
|---|---|
| txt · md · csv · tsv · json · log | ✅ |
| **docx** | ✅ แตก zip และอ่าน xml เอง |
| **xlsx** | ✅ อ่าน sharedStrings และ sheet ได้ถึง 3 แผ่น 300 แถว |
| **pdf** | ⚠️ เฉพาะ PDF ที่เป็นข้อความจริง ถ้าอ่านไม่ออกจะบอกตรง ๆ ไม่ส่งขยะให้โมเดล |
| doc · xls รุ่นเก่า | ❌ คนละรูปแบบไฟล์ ต้องแปลงเป็น docx/xlsx ก่อน |
| **รูปภาพ** | ❌ ดูหัวข้อ 3 |

**รันโค้ด** — เฉพาะ JavaScript รันใน Web Worker ที่แยก scope จากหน้าเว็บ
ตัดทิ้งเมื่อเกิน 4 วินาที ทดสอบแล้ว: ลูปไม่รู้จบถูกตัด · แตะ DOM ไม่ได้
(`document is not defined`) · error ถูกจับมาแสดง

**บทบาทงานเขียนโค้ด** — ดัน Codestral ขึ้นเป็นตัวแรก พร้อมระบุว่าเป็นคำอธิบาย
ของผู้ผลิต ไม่ใช่ผลวัดของเรา

## 3. สิ่งที่ทำไม่ได้ และเหตุผล

**รูปภาพ / OCR** — โมเดลรูปทุกตัวในรายการตอบ `unsupported_model_feature`
ไม่มีโมเดลฟรีตัวไหนรับรูปได้เลย การทำ OCR ในเบราว์เซอร์ต้องโหลดไลบรารี
หลายเมกะไบต์จากภายนอก ซึ่งจะทำให้หน้านี้เลิกเป็นไฟล์เดียวที่เปิดออฟไลน์ได้
**ตอนนี้ระบบปฏิเสธไฟล์รูปพร้อมบอกเหตุผล ไม่ใช่เงียบ ๆ**

**รัน Python** — ต้องโหลดตัวแปลภาษาขนาดสิบกว่าเมกะไบต์ ระบบจึงบอกตรง ๆ
ใต้บล็อกโค้ด Python ว่ารันไม่ได้ แทนที่จะซ่อนปุ่ม

**PDF สแกน** — ไม่มีข้อความให้ดึง ต้องใช้ OCR ซึ่งติดข้อจำกัดเดียวกัน

## 4. งานการแพทย์และสุขภาพ — ไม่ควรทำเป็นฟีเจอร์

ข้อมูลที่มีบอกว่าไม่ควร ไม่ใช่แค่ควรระวัง

- งานจำแนกประเภทวัดได้ **33–50%** ทุกโมเดล และ **φ = +1.000** คือผิดข้อเดียวกันหมด
  การที่โมเดลตอบตรงกันจึงไม่ใช่หลักฐานว่าถูก ซึ่งเป็นสมมติฐานหลักของหน้านี้
- โมเดลที่ใช้อยู่คือรุ่นเล็กที่แจกฟรี ไม่ใช่รุ่นที่ผ่านการประเมินด้านการแพทย์
- ความพร้อมใช้งานแกว่งรายวัน ระบบที่คนใช้ตัดสินใจเรื่องสุขภาพต้องไม่ล่มแบบนี้

**สิ่งที่ทำได้อย่างปลอดภัย**: ใช้เป็นตัวช่วย *อ่านเอกสาร* เช่นสรุปผลแล็บที่ผู้ใช้
แนบมา หรือเรียบเรียงคำถามก่อนไปพบแพทย์ โดยห้ามให้คำวินิจฉัย ห้ามแนะนำยา
หรือขนาดยา และต้องมีคำเตือนติดทุกคำตอบ **ยังไม่ได้ทำ** เพราะต้องออกแบบ
คำเตือนและขอบเขตให้รัดกุมกว่านี้ก่อน

## 5. งานวิศวกรรม — ทำได้ แต่ต้องวัดก่อน

โครงที่มีอยู่รองรับได้ทันที (เพิ่มบทบาท + ชุดทดสอบ + ตัวตรวจ) แบบเดียวกับที่
ทำกับงานคำนวณและงานเขียน สิ่งที่ต้องมีคือ **ชุดทดสอบที่ตรวจอัตโนมัติได้**
เช่นโจทย์ที่มีคำตอบตายตัวจากสูตร (โหลดไฟฟ้า ขนาดสายไฟ แรงดันตก โมเมนต์ดัด)
ซึ่งเป็นงานสร้างชุดข้อสอบ ไม่ใช่งานเขียนโปรแกรม

**ห้ามเพิ่มเมนู "วิศวกรรม" โดยไม่มีตัวเลขรองรับ** เพราะจะกลายเป็นการอ้าง
ความสามารถที่ไม่ได้พิสูจน์ ซึ่งเป็นสิ่งที่ CLAUDE.md ห้ามไว้

## 6. สิ่งที่ยังขาดสำหรับการใช้งานจริง เรียงตามความสำคัญ

1. **ความน่าเชื่อถือของผู้ให้บริการ** — 2 ใน 5 ตัวที่ดีที่สุดล่มพร้อมกันได้
   ทางแก้คือเพิ่มผู้ให้บริการรายที่สอง ไม่ใช่เพิ่มโมเดลจากรายเดิม
2. **ตรวจสถานะโมเดลอัตโนมัติ** — ตอนนี้รายชื่อฝังไว้ในโค้ด ถ้าโมเดลตาย
   ผู้ใช้เจอ error เอง ควรเรียก `/v1/models` ตอนเปิดหน้าแล้วปิดตัวที่ไม่พร้อม
3. **ประวัติการสนทนาหลายห้อง** — ตอนนี้มีห้องเดียว เก็บใน localStorage
4. **ส่งออกบทสนทนา** — เป็น md หรือ docx
5. **วัดหมวดที่ยังไม่มีข้อมูล** — เขียนงาน โค้ด และวิศวกรรม
6. **ไฟล์แนบขนาดใหญ่** — ตอนนี้ตัดที่ 12,000 ตัวอักษร เอกสารยาวกว่านั้น
   ต้องแบ่งเป็นส่วนแล้วค้นเฉพาะส่วนที่เกี่ยวข้อง (RAG) ซึ่งต้องมีตัวแปลง
   ข้อความเป็นเวกเตอร์ และยังไม่มีตัวไหนฟรีที่เรียกจากเบราว์เซอร์ได้
