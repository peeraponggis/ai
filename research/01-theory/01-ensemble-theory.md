# 01 — ทฤษฎีแกน: ทำไมหลายโมเดลถึงแม่นกว่าโมเดลเดียว (และเมื่อไหร่ที่ไม่จริง)

> สถานะ: ฉบับแรก · วันที่ 2026-08-23 · ทุกข้ออ้างอิงมีลิงก์ท้ายเอกสาร

## 0. โจทย์

ใช้โมเดลฟรี (ไม่ต้องมี API key หรือ free tier) ซึ่งแต่ละตัว **อ่อนกว่า** โมเดลเสียเงิน
มาวิเคราะห์ข้อมูลให้ได้คุณภาพใกล้เคียงหรือดีกว่าโมเดลเดี่ยวที่แพงกว่า
โดยต้อง **บอกได้เป็นตัวเลขว่าคำตอบนั้นน่าเชื่อถือแค่ไหน**

ทฤษฎีที่เกี่ยวข้องแบ่งได้เป็น 3 กลุ่ม:

| กลุ่ม | ตอบคำถามว่า |
|---|---|
| A. ทฤษฎีการรวมความเห็น | รวมคำตอบหลายชุดแล้วดีขึ้นเพราะอะไร ดีขึ้นเท่าไหร่ |
| B. โครงสร้างการทำงานร่วมกัน | จัดให้โมเดลคุยกัน/ตรวจกันแบบไหนได้ผล |
| C. การวัดความมั่นใจ | จะแปลง "ความเห็นพ้อง" เป็น "ความน่าจะเป็นที่ถูก" ได้อย่างไร |

## A. ทฤษฎีการรวมความเห็น

### A1. Condorcet Jury Theorem (1785) — รากฐานทางคณิตศาสตร์

ถ้ามีผู้ลงคะแนน `n` คน แต่ละคนตอบถูกด้วยความน่าจะเป็น `p` **อย่างเป็นอิสระต่อกัน**
ความน่าจะเป็นที่เสียงข้างมากจะถูกคือ

```
P_maj(n, p) = Σ[k = ⌊n/2⌋+1 → n]  C(n,k) · p^k · (1−p)^(n−k)
```

คำนวณจริง (สคริปต์ในเอกสารนี้):

| p (โมเดลเดี่ยว) | n=1 | n=3 | n=5 | n=7 | n=9 |
|---|---|---|---|---|---|
| 0.55 | 55.0% | 57.5% | 59.3% | 60.8% | 62.1% |
| 0.60 | 60.0% | 64.8% | 68.3% | 71.0% | 73.3% |
| **0.70** | 70.0% | **78.4%** | **83.7%** | 87.4% | 90.1% |
| 0.80 | 80.0% | 89.6% | 94.2% | 96.7% | 98.0% |
| **0.45** | 45.0% | **42.5%** | **40.7%** | 39.2% | 37.9% |

**บทเรียนสองข้อที่ใช้ตัดสินใจได้ทันที**

1. โมเดลฟรีที่ถูก 70% จำนวน 5 ตัว → เสียงข้างมากถูก **83.7%** ซึ่งเทียบเท่าโมเดลเดี่ยวระดับดี
   นี่คือเหตุผลเชิงทฤษฎีที่ทำให้แนวทาง "โมเดลฟรีหลายตัว" มีที่ยืน
2. **ถ้าโมเดลแย่กว่าการเดา (p < 0.5) การโหวตยิ่งทำให้แย่ลง** — ที่ p=0.45 ยิ่งเพิ่มโมเดล
   ยิ่งดิ่ง (45% → 37.9%) ดังนั้น **ต้องคัดโมเดลที่ผ่านเกณฑ์ก่อนเสมอ** ห้ามโยนทุกตัวเข้าโหวต

### A2. ข้อสมมติที่พังในทางปฏิบัติ: ความเป็นอิสระ

โมเดลจริงไม่ได้ตอบอิสระต่อกัน — เทรนจากข้อมูลเว็บชุดใกล้เคียงกัน สถาปัตยกรรมคล้ายกัน
หลายตัวกลั่นความรู้มาจากโมเดลใหญ่ตัวเดียวกัน **จึงผิดพร้อมกันในเรื่องเดียวกัน**

ประมาณผลกระทบด้วยจำนวนผู้ลงคะแนนที่ใช้ได้จริง (effective sample size)
เมื่อความสัมพันธ์ของความผิดพลาดเฉลี่ย = ρ:

```
n_eff ≈ n / (1 + (n−1)·ρ)
```

| ρ | n=5 → n_eff | P_maj ที่ p=0.7 |
|---|---|---|
| 0.0 | 5.00 | 83.7% |
| 0.2 | 2.78 | ~78.4% |
| 0.4 | 1.92 | ~78.4% |
| 0.6 | 1.47 | ~70.0% (เท่าโมเดลเดียว) |
| 0.8 | 1.19 | ~70.0% (เท่าโมเดลเดียว) |

**นัยสำคัญที่สุดของทั้งเอกสาร**: ที่ ρ ≈ 0.6 ขึ้นไป การเพิ่มโมเดลแทบไม่ให้อะไรเลย
→ **ความหลากหลายของโมเดลสำคัญกว่าจำนวนโมเดล** เลือกคนละค่าย คนละวิธีเทรน
ดีกว่าเลือกโมเดลตระกูลเดียวกัน 5 ตัว และ ρ เป็นสิ่งที่ **ต้องวัด** ไม่ใช่เดา

งานฝั่ง ensemble learning ดั้งเดิมเตือนไว้ตรงกัน: Kuncheva & Whitaker สำรวจดัชนีวัด
ความหลากหลาย 10 แบบ แล้วพบว่า **ไม่มีตัวไหนทำนายความแม่นของ ensemble ได้น่าเชื่อถือ**
→ อย่าหวังพึ่งสูตร ต้องวัดผลจริงบนงานของเราเอง

### A3. Self-Consistency — โหวตจากโมเดลตัวเดียว

Wang et al. (2022) เสนอ **self-consistency**: สุ่มเส้นทางคิด (reasoning path) หลายเส้น
จากโมเดล *ตัวเดียวกัน* แล้วโหวตคำตอบสุดท้าย ได้ผลดีขึ้นชัดเจนบนงาน reasoning

- **ข้อดีสำหรับเรา**: ใช้ได้แม้มีผู้ให้บริการฟรีเจ้าเดียว
- **ข้อจำกัด**: ρ สูงมากโดยธรรมชาติ (โมเดลเดียวกัน อคติเดียวกัน) → เพดานต่ำกว่าการใช้หลายโมเดล
- **คำเตือนที่มีงานรองรับ**: มีงานที่พบว่า majority vote **ทำให้แย่ลง** กับโจทย์วิทยาศาสตร์ยาก
  ในโมเดลเล็ก — ตรงกับกรณี p < 0.5 ในตาราง A1

## B. โครงสร้างการทำงานร่วมกัน

เรียงจากถูก/เร็ว → แพง/ช้า (ต้นทุนนับเป็น "จำนวน request" เพราะโมเดลฟรีจำกัดที่อัตราเรียก)

| # | วิธี | จำนวน request | ใช้เมื่อ |
|---|---|---|---|
| 1 | **Majority Vote** | n | คำตอบเป็นค่าที่เทียบเท่ากันได้ (ตัวเลข/ตัวเลือก/ข้อสรุปสั้น) |
| 2 | **Chain-of-Verification (CoVe)** | 1 + k + 1 | งานที่ต้องกันการกุข้อเท็จจริง ใช้โมเดลเดียวได้ |
| 3 | **Mixture-of-Agents (MoA)** | n × layers + 1 | งานเขียน/สังเคราะห์ที่ไม่มีคำตอบเดียว |
| 4 | **Multi-Agent Debate** | n × rounds + 1 | โจทย์ที่คำตอบขัดแย้งกันและต้องหาเหตุผลชี้ขาด |
| 5 | **LLM-as-a-Judge** | n + m | ต้องให้คะแนน/จัดอันดับผลลัพธ์ |

### B1. Mixture-of-Agents (Wang et al., 2024)

จัดโมเดลเป็นชั้น ๆ แต่ละชั้นเห็นผลลัพธ์ของชั้นก่อนหน้าแล้วเขียนใหม่ให้ดีขึ้น
**ผลที่รายงาน: MoA ที่ใช้เฉพาะโมเดลโอเพนซอร์สได้ 65.1% บน AlpacaEval 2.0
เหนือกว่า GPT-4 Omni ที่ 57.5%** และไม่ต้อง fine-tune อะไรเลย

→ นี่คือหลักฐานตรงที่สุดว่า **โมเดลฟรีหลายตัวเอาชนะโมเดลเสียเงินตัวเดียวได้จริง**
แต่ต้องระวัง: AlpacaEval วัดคุณภาพการเขียนตอบ ไม่ใช่ความถูกต้องเชิงตัวเลข

### B2. Chain-of-Verification (Dhuliawala et al., 2023)

ร่างคำตอบ → **สร้างคำถามตรวจสอบ** → ตอบคำถามตรวจสอบ *แบบไม่เห็นร่างเดิม*
(สำคัญมาก เพื่อไม่ให้ลำเอียงตามร่าง) → เขียนคำตอบฉบับแก้ไข
ลดการกุข้อมูลได้ทั้งงานตอบรายการ, QA และงานเขียนยาว

### B3. Multi-Agent Debate (Du et al., 2023)

หลายอินสแตนซ์เสนอคำตอบ เห็นของกันและกัน แล้วโต้แย้ง/แก้ไขหลายรอบจนได้ข้อสรุปร่วม
เพิ่มความถูกต้องเชิงข้อเท็จจริงและลด hallucination

⚠️ มีงานตรงข้ามที่พบว่า debate ระหว่างโมเดล **ชนิดเดียวกัน** สู้การให้แต่ละตัว
แก้ตัวเองแบบแยกกันไม่ได้ — สอดคล้องกับ A2: debate ได้ผลก็ต่อเมื่อผู้ร่วมวงต่างกันจริง

### B4. LLM-as-a-Judge (Zheng et al., 2023) — และอคติที่ต้องกันไว้ก่อน

GPT-4 ในฐานะกรรมการเห็นตรงกับมนุษย์ ~85% ซึ่ง **สูงกว่าที่มนุษย์เห็นตรงกันเอง (81%)**
แต่เอกสารเดียวกันระบุอคติ 3 อย่างที่ต้องออกแบบป้องกัน:

| อคติ | อาการ | วิธีกัน |
|---|---|---|
| **Position bias** | ชอบตัวเลือกที่วางก่อน | สลับลำดับแล้วตัดสินสองครั้ง เอาผลที่คงเส้นคงวา |
| **Verbosity bias** | ชอบคำตอบยาวแม้ไม่ดีกว่า | กำหนดเกณฑ์ให้ชัด/ตัดคะแนนความยาว |
| **Self-enhancement bias** | ชอบผลงานของตัวเอง | **ห้ามให้โมเดลตัดสินคำตอบของตัวเอง** |

## C. การวัดความมั่นใจ (จุดที่ทำให้ "ประเมินความสำเร็จ" เป็นตัวเลขได้)

### C1. สัดส่วนความเห็นพ้อง ≠ ความน่าจะเป็นที่ถูก

ถ้า 4 ใน 5 โมเดลตอบตรงกัน **ห้ามสรุปว่าถูก 80%** — ค่านี้ต้องผ่านการ *calibrate*
กับข้อมูลจริงก่อน เพราะเมื่อโมเดลมี ρ สูง ความเห็นพ้องจะสูงเกินจริงอย่างเป็นระบบ

วิธีที่ถูกต้อง: เก็บชุดทดสอบที่รู้คำตอบจริง → สร้างฟังก์ชันแมป
`สัดส่วนเห็นพ้อง → ความน่าจะเป็นที่ถูก` (เช่น logistic regression / isotonic regression)
→ แล้ววัดคุณภาพของการแมปด้วย:

- **Brier score** = ค่าเฉลี่ยของ `(p̂ − y)²` — ยิ่งต่ำยิ่งดี (0 = สมบูรณ์แบบ)
- **ECE (Expected Calibration Error)** = ผลต่างเฉลี่ยระหว่างความมั่นใจกับความแม่นจริง
  แบ่งเป็นช่วง ๆ แล้วถ่วงน้ำหนักตามจำนวนตัวอย่าง

### C2. Semantic Entropy (Farquhar et al., Nature 2024)

แทนที่จะวัดความต่างของ *ข้อความ* ให้จัดกลุ่มคำตอบที่ **มีความหมายเดียวกัน** ก่อน
แล้วค่อยคำนวณเอนโทรปีจากการกระจายของกลุ่มความหมาย — ใช้ตรวจจับ *confabulation*
(กรณีที่โมเดลมั่วเพราะไม่รู้) ได้ดีกว่าการวัดความต่างระดับตัวอักษร

**ทำไมสำคัญกับเรา**: การโหวตแบบเทียบสตริงตรง ๆ จะนับ "4.7 บาท/หน่วย" กับ
"4.70 บาทต่อหน่วย" เป็นคนละคำตอบ → ต้องมีขั้นตอนจัดกลุ่มเชิงความหมายก่อนโหวตเสมอ

## D. สรุปเป็นหลักการออกแบบ 7 ข้อ

1. **คัดก่อนโหวต** — โมเดลที่ p < 0.5 บนงานของเราต้องถูกตัดออก ไม่งั้นยิ่งรวมยิ่งแย่
2. **หลากหลายมาก่อนจำนวน** — 3 โมเดลต่างค่าย ดีกว่า 7 โมเดลตระกูลเดียวกัน
3. **วัด ρ จริง** — ความสัมพันธ์ของความผิดพลาดคือตัวแปรที่กำหนดเพดานทั้งระบบ
4. **จัดกลุ่มความหมายก่อนนับคะแนน** — ไม่เทียบสตริงดิบ
5. **แยกบทบาทผู้ตอบกับกรรมการ** — และห้ามตัดสินงานตัวเอง
6. **ความมั่นใจต้อง calibrate** — รายงานเป็นตัวเลขได้ก็ต่อเมื่อผ่าน Brier/ECE แล้ว
7. **เลือกวิธีตามงบ request** — โมเดลฟรีจำกัดที่อัตราเรียก ไม่ใช่ที่เงิน

## E. สิ่งที่ยังไม่รู้ (ต้องทดลองวัดเอง)

- ρ จริงระหว่างโมเดลฟรีที่หาได้ (Pollinations / LLM7 / Puter) — ยังไม่มีใครวัดไว้
- p จริงของแต่ละโมเดลบน **งานวิเคราะห์ข้อมูลภาษาไทย** ซึ่งต่างจาก benchmark อังกฤษ
- ผลของ rate limit ต่อการออกแบบ: 1 req/15s ทำให้ debate หลายรอบใช้ไม่ได้จริงหรือไม่
- คำตอบเชิงตัวเลขกับเชิงข้อความต้องใช้วิธีรวมคนละแบบหรือไม่
